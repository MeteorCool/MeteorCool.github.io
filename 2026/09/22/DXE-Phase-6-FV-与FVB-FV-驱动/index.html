DXE Phase(6) FV 与FVB FV 驱动

DXE foundation 提供的FV 驱动和FVB 一样是只读版本，所有协议当中的写函数仅仅做EFI_UNSUPPORTED的返回值。

FV 驱动的入口函数FwVolDriverInit

注册一个 FirmwareVolumeBlock 协议的通知事件，每当系统里安装 / 新增 FVB 协议实例时，回调 NotifyFwVolBlock 自动执行。

回调函数：NotifyFwVolBlock

功能监听每一个新上报的 FVB（FirmwareVolumeBlock）Handle，在同一个 Handle 上按需安装 FV2 协议；FV2 是上层读 FFS 文件的协议，FVB 是底层 Flash 块读写协议。

通过for 循环实现所有corelocatehandle 的遍历运行，ByRegisterNotify 是专门给 RegisterProtocolNotify 配套的查找方式：

UEFI 在你注册 notify 之后，会维护一个待处理的 Handle 队列，每次调用 ByRegisterNotify + RegistrationToken(gEfiFwVolBlockNotifyReg)，取出队列里下一个待处理 Handle，同时把它从待处理队列移除。队列空了，返回 EFI_NOT_FOUND，break 循环

CoreHandleProtocol 是 BootService HandleProtocol 的内部内核版本：打开当前 Handle 上的 FVB 接口。

读取并且校验header
VerifyFvHeaderChecksum：校验 FV Header 的 Checksum，FV 规范要求 header 校验和为 0；校验失败说明 Flash 上 FV 头损坏，直接释放内存、跳过这个 FV，不继续创建 FV2

分支1：Handle 上已经存在 gEfiFirmwareVolume2ProtocolGuid（Fv 不为空）

  1. 已经装过 FV2 协议了 → 用 BASE_CR 从 Fv 接口指针反向拿到我们自定义的 FV_DEVICE 结构体首地址
  2. 校验 FV2_DEVICE_SIGNATURE：确认这个 FV2 实例确实是我们这个驱动创建的，不是别的驱动安装的 FV2（防止越界修改第三方 FV2）
  3. 更新：把 Fvb 指针刷新成当前新的 FVB

适用场景：FVB 实例被重新枚举、Flash 设备热插拔、FVB 协议重装，同步更新底层 FVB 指针，上层 FV2 接口不用重新安装，无缝切换底层 Flash 后端。

分支2：Handle 上没有 FV2 协议 → 新建 FV_DEVICE、安装 FV2 协议

前半段填充私有字段，后半段进行认证：

  • FvCheck(FvDevice)：驱动内部额外校验（比如检查 FV 里 FFS 目录合法、大小合法等，比 Header Checksum 更深入）

  • 校验通过：

    在同一个原始 FVB 的 Handle 上，追加安装 FV2 协议

    ✅ 非常关键：FVB Handle 同时挂载 FVB + FV2 两个协议，上层 DXE 驱动 Locate FV2 时就能找到这个 FV，读取里面的 FFS 文件

  • 校验失败：释放刚分配的 FvDevice，不安装 FV2，跳过这个损坏 FV

循环回到头部，继续运行 ByRegisterNotify 队列里下一个 Handle。队列空，退出循环，回调返回。

FvCheck是上面NotifyFwVolBlock 里的FV 完整性校验 + FV 缓存构建 + FFS 文件扫描建表函数

输入：半成品 FV_DEVICE（已经绑定 Fvb、FV Header） 输出：

  • EFI_SUCCESS：FV 合法，FV_DEVICE 内部缓存、FFS 链表全部建好，可以对外安装 FV2 协议
  • 非 SUCCESS：FV 损坏 / 资源不足，上层会释放 FvDevice、放弃安装 FV2 一句话概括：把整个 FV 读到内存（或者直接映射），从头到尾遍历所有 FFS 文件，校验每个 FFS 头、文件 checksum，构建本 FV 的 FFS 文件链表，供 FV2 的 ReadSection/GetNextSection 后续快速查询

note:

FVB 只是块读写；FV2 协议要快速查找 FFS 文件、Section，驱动需要在内存里缓存 FV 内容 + 建立 FFS 文件链表索引，这个函数就是一次性初始化这个索引和缓存。 区分两个 FV：

  • FFS2：老格式，文件大小 24bit 上限（0xFFFFFF）
  • FFS3（FFS_FILE2）：新格式，支持 > 16MB 大文件，对应 EFI_FFS_FILE_HEADER2

  • ：Flash 直接映射到系统物理地址（SPI Flash、BIOS ROM 最常见）

    • ✅ 不需要内存拷贝，CachedFv 直接指向 Flash 映射地址，节省内存、省时间
    • ⚠️ 但是 Flash 是 MMIO，不能直接随便读做 checksum（或者有些场景需要拷贝单文件），后面会看到这个分支的特殊处理

  • 非 MemoryMapped：比如一些外接存储、虚拟 FV，调用 AllocatePool 分配一整块内存，把整个 FV 全部读进内存缓存

  • EndOfCachedFv：缓存尾指针，后面遍历 FFS 的时候用来做边界保护，防止越界

非内存映射 FV：按 BlockMap 逐块读取 Flash 到 CachedFv

BlockMap 是 FV 规范定义的数组：{NumBlocks, BlockLength}，以 {0,0} 结尾 举例子：{16,0x1000} = 16 个块，每块 4KB

  • 循环遍历每一个 BlockMap 表项，按 LBA 顺序调用 FVB->Read，把 Flash 内容拷贝到刚才分配的 CachedFv
  • 任何一块读失败 → 直接跳 Done，标记 FV 损坏

注：这里是卡 Flash 硬件故障的经典点位：SPI 读取异常、FW 卷损坏、Flash 不稳定，都会在这里返回错误。

Flash 擦除极性：

  • 1：擦除后是 0xFF（绝大多数 SPI Flash）
  • 0：擦除后是 0x00 后面 IsBufferErased()、IsValidFfsHeader()、IsValidFfsFile() 全部依赖这个极性判断空白区域、已删除文件。

初始化 FFS 链表头，定位第一个 FFS 文件起始位置

  • FV 可以带扩展头（ExtHeader），扩展头之后才是 FFS 文件区域；没有扩展头就从 FV 主头结束位置开始
  • UEFI FFS 规范强制：FFS 文件头必须 8 字节对齐，ALIGN_POINTER 对齐指针

主循环：逐个遍历 FV 内所有 FFS 文件，边界条件：指针不能超出 FV 缓存范围，至少还能放下一个 FFS 头，防止越界。IsBufferErased：判断这块区域是不是全是擦除值（0xFF/0x00）

UEFI FV 布局规则：FFS 文件连续排列，遇到整块空白擦除区域，代表 FFS 文件列表结束，直接退出遍历。这是 FV 的结束标记。

FFS 头校验 IsValidFfsHeader：

FileState 几种状态：

  • EFI_FILE_HEADER_CONSTRUCTION：文件正在写入构建中（固件升级过程中中间态），直接跳过
  • EFI_FILE_HEADER_INVALID：头非法，跳过
  • 其他错误状态：判定 FV 损坏，返回 EFI_VOLUME_CORRUPTED

这里区分 IS_FFS_FILE2：看 FFS 头里的标记位，判断是 FFS2（老）还是 FFS3（Header2）

  • FFS_ATTRIB_CHECKSUM：这个 FFS 文件需要做整文件 checksum 校验
  • 如果是 MMAP FV（直接指向 Flash MMIO）：不能直接在 MMIO 地址上做 checksum 计算（部分 Flash MMIO 读有副作用、速度慢、或者读不稳定）
  • 所以单独分配内存，把这个 FFS 完整拷贝一份到内存，用副本做校验；FileCached=TRUE 标记这个副本后面要释放
  • 非 MMAP FV：整个 FV 已经在 CachedFv 内存里，不需要单独拷贝

校验整个 FFS 文件合法性 IsValidFfsFile IsValidFfsFile：校验 FFS 文件的 checksum、文件状态、字段合法性，校验失败直接判定 FV 损坏。

校验 FFS3 文件不能放在非 FFS3 FV 里

规范约束：

  • FFS3（FILE2）文件只能存在于 FileSystemGuid = gEfiFirmwareFileSystem3Guid 的 FV里面
  • 如果 FV 是 FFS2，但是里面出现 FFS3 文件 → 打印 error，跳过这个文件，不直接报错（兼容容错）
  • EFI_FILE_DELETED：标记为已删除的 FFS 文件，不加入链表，上层 FV2 查找的时候看不见
  • 有效文件：分配 FFS_FILE_LIST_ENTRY 链表节点，挂到 FvDevice->FfsFileListHeader

这个链表就是 FV2 协议 GetNextFile / ReadSection 的索引！后续上层驱动找 FFS 文件，直接遍历这个内存链表，不用反复扫描 Flash。

指针前进，8 字节对齐，准备下一个 FFS

按当前文件大小跳过，再 8 字节对齐，继续循环下一个 FFS。

Done 收尾分支

只要前面任意步骤出错（读 Flash 失败、FV 损坏、内存分配失败）：

  1. 释放刚才单独拷贝的 FFS 缓存（如果有）
  2. FreeFvDeviceResource：释放 CachedFv、已经分配好的 FFS 链表节点等所有资源
  3. 返回错误码给 NotifyFwVolBlock

NotifyFwVolBlock 收到错误，就不会调用 CoreInstallProtocolInterface 安装 FV2 协议，这个 FV 直接被丢弃。
