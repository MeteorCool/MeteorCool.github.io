DXE Foundation 包含了内置的FVB 和FV 驱动，FVB 驱动为通过FV HOB 上报的每一个FV安装提供了只读服务的EFI_FIRMWARE_VOLUME_BLOCK_PROTOCOL的实例，FV 驱动在EFI_FIRMWARE_VOLUME_BLOCK_PROTOCOL的基础上安装了只提供只读服务的EFI_FIRMWARE_VOLUME2_PROTOCOL 的实例，DXE Foundation 使用EFI_FIRMWARE_VOLUME2_PROTOCOL 在FV上寻找并读取A priori文件，DXE驱动和UEFI 驱动。

Firmware Volume Block 驱动

**FwVolBlockDriverInit()**函数是内置的 Firmware Volume Block 驱动的入口函数。

函数功能，获取HOB header，遍历hob为每一个fv hob报告的FV 调用ProduceFVBProtocolOnBuffer 函数安装FVB protocol。

CoreProcessFirmwareVolume函数是 ProcessFirmwareVolume() DXE Service 的实现。这个DXE service主要用来处理capsule 的FV.

输入内存中一整块 FV 镜像二进制，调用ProduceFVBProtocolOnBuffer在内存上创建内存版 FVB Protocol 与 Handle； 然后校验该 Handle 上是否成功生成 FV2 协议。

  • 成功：返回 Handle，FV2 的 notify 事件触发，再调用另一个同名 CoreProcessFirmwareVolume 去扫描 FV 里所有驱动（递归）

  • 校验失败：返回EFI_VOLUME_CORRUPTED，标记这个内嵌 FV 镜像损坏。

    ProduceFVBProtocolOnBuffer()函数

上述两个函数安装FVB protocol 的核心函数就是此函数，函数功能总结如下：传入一块内存 / MMIO 物理地址的 FV 区域，校验 FV 头部签名与对齐，创建 FVB 私有设备上下文EFI_FW_VOL_BLOCK_DEVICE，解析 FV BlockMap 并构建 LBA 缓存，创建设备路径，新建 EFI Handle 并安装 FVB Protocol + DevicePath Protocol；输出新建 Handle

FwVolBlockGetPhysicalAddress()函数

​ 查询当前固件卷 (FV) 的物理基地址。仅当 FV 是内存映射（Memory Mapped）类型时，返回 FV 起始物理地址；否则返回 EFI_UNSUPPORTED，不支持获取物理地址。
