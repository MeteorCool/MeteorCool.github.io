​ 内存服务

PeiInstallPeiMemory 安装 PEI 阶段可用的内存空间。

安装 PEI 阶段可用的永久内存，此服务最多使用一次，不支持内存的多次安装。输入参数是 PEI 服务指针及永久内存的起始地址及大小，返回值是安装成功的状态值。

还是通过PEI_CORE_INSTANCE_FROM_PS_THIS 函数，通过PeiServices反向找到peicore 得数据结构

判断内存是否安装，如果永久内存已经安装，则不能再次安装，否则系统无法正确处理。

记录永久内存的起始地址及大小，PeiCore 将用安装的永久内存作为系统内存进行维护。 设置内存标记，表明系统内存已经安装，函数的运行栈空间需要切换到内存空间。

参考PI SPEC 1.9 III-4.3，PEI 内存分配如图：

PeiAllocatePages ，分配 PEI 管理的内存空间，以页为单位申请。此服务只有在内存空间被安装以后才可以使用。

以页为基本单元申请内存空间，一页默认为4kb内存，通常申请大段的内存空间会用到此服务。它只有在系统内存被安装以后才可以使用，这是因为临时内存没有足够的空间.

对内存类型进行检查，只支持所列的内存类型。如果是不支持的内存类型，则返回不合法的状态值。

像 EfiConventionalMemory(普通可用内存)不能通过该接口申请，直接返回参数非法，因为常规可用内存由 PHIT 管理，AllocatePages 专门用于启动阶段专用类型内存。

HOB 链表为空 = PEI 环境还没初始化完成内存资源，分配接口暂不可用，返回 EFI_NOT_AVAILABLE_YET。

Runtime 运行时服务内存、ACPI‑NVS、保留内存要求更大的硬件对齐粒度（常见 64KB / 1MB），适配 MMU、缓存属性、运行时虚拟地址映射约束。当申请上述内存则需要变更默认对齐粒度大小(一页大小)。

  1. 分支 1：临时内存 (TempRam) 阶段

    • PeiMemoryInstalled = false：永久内存还没安装；
    • SwitchStackSignal = true：已经从临时栈切换；
    • 空闲内存取自 PEI 内核实例内保存的物理内存起止。

  2. 分支 2：永久内存 + 开启内存桶 Memory‑Bin

    UEFI 支持为不同 MemoryType 划分独立内存池。

    MemoryTypeStatistics[MemoryType] 存储该类型专属空闲内存上下限，优先从专属内存桶分配，避免多种内存类型地址混杂。

  3. 分支 3：默认 PHIT（Pei Handoff Information Table）全局空闲内存池

    当没有开启对应类型内存桶，则使用 PHIT 全局空闲内存。PHIT 保存在 HOB 链表的 HandOffInformationTable，是 PEI 最顶层的全局空闲内存标记。

第一次优先尝试当前选中的内存桶；

如果分配失败、内存桶可用，则切换到 PHIT 全局空闲池再试一次；

两次失败之后，遍历所有内存分配 HOB 寻找空闲块。

FindFreeMemoryFromMemoryAllocationHob 遍历整条 HOB 链表，扫描已经释放、标记为常规可用内存的 HOB 块，寻找满足对齐、页数量要求的空闲内存； HOB 遍历分配成功直接返回； 全部途径失败，打印错误日志，返回资源耗尽 EFI_OUT_OF_RESOURCES。

PeiAllocatePool 分配 PEI 管理的内存空间，以字节为单位申请

PEI 早期 Temporary Ram（临时内存） 通常只有 64KB 大小；所有 HOB 结构体总长度强制要求是 8‑字节对齐；0xFFF8 = 64KB (0x10000) 减去 8；还要扣除 EFI_HOB_MEMORY_POOL 头部结构体占用空间；所以单次 Pool 分配上限

= 0xFFF8 − sizeof(EFI_HOB_MEMORY_POOL)。

用户申请大小超出单次 Pool 分配上限，直接返回资源不足；这里并不是真的系统没有内存，而是 MEMORY_POOL 类型 HOB 本身有长度硬性约束。

PeiServicesCreateHob 函数逻辑：

  1. 从 PHIT 空闲内存顶端向下取出一块内存；
  2. 完成 8 字节对齐；
  3. 初始化 HOB 通用头部、HOB‑MemoryPool 结构体；
  4. PHIT 空闲指针往下偏移占用掉的内存。

函数内参数说明：

EFI_HOB_TYPE_MEMORY_POOL：HOB 类型标记，代表这块 HOB 属于 PEI 堆池内存；

HOB 总长度 = 头部 EFI_HOB_MEMORY_POOL + 用户需要的缓冲区 Size；

输出参数 Hob：返回新建 HOB 结构体首地址。

(EFI_PEI_COPY_MEM)CopyMem 复制一段数据从源地址到目的地址

(EFI_PEI_SET_MEM)SetMem 设置一段内存空间为输入的具体数值

状态报告服务：

PeiReportStatusCode ，报告状态编码，PEI模块可以使用这个服务报告系统运行过程中的状态。

加载系统中已经安装的 PeiStatusCodePpi。
如果 PeiStatusCodePpi 已经安装，则调用 PeiStatusCodePpi 服务报告输入的状态编码，并返回状态值。
如果 PeiStatusCodePpi 没有安装，则本函数无法报告输入的状态编码，返回服务不可用的状态值。

系统重启服务：

PeiResetSystem 重启整个系统，包括处理器和各种设备

PeiResetSystem 是 PEI 内核提供的 PeiServices‑>ResetSystem 接口实现，负责在 PEI 预初始化阶段执行系统硬件复位。

整体调用优先级：优先调用增强版 PeiResetSystem2 → 查找复位 PPI → 报错返回复位服务不可用。

Note: PeiResetSystem2 是增强复位接口，支持多种复位类型（冷复位、热复位、关机、特定平台复位）；

如果函数执行成功触发硬件复位，CPU 直接重启，后续代码永远不会运行；

函数返回 = 平台没有实现 ResetSystem2，继续往下走旧版复位逻辑。

通过调用ResetPpi 完成重启。

PeiResetSystem2

调用 PEI 服务去搜寻 GUID 为 gEfiPeiReset2PpiGuid 的复位 2 协议。

该 PPI 由平台硬件 PEIM 负责安装，内部封装芯片 PMC、看门狗、GPIO、复位寄存器等平台专属硬件操作。

成功找到 Reset2Ppi，则调用平台实现的 ResetSystem 接口，把全部复位参数向下传递。

IO 服务

&gPeiDefaultCpuIoPpi 提供IO，内存得读写

&gPeiDefaultPciCfg2Ppi 提供PCI 接口访问

其他服务：

PeiFfsFindFileByName 在当前的 FV 数据空间通过文件 GUID 查找文件存储单元。

在输入的 FV 数据空间中，根据文件 GUID，查找对应的文件句柄。该函数的实现是基于 FvPpi 的 FindFileByName()服务。

根据 FV 句柄查找对应的 PeiCore 内部维护的 FV 句柄结构。

如果对应的 PeiCore 内部维护的 FV 句柄结构没有找到，或者该 FV 数据结构的 FvPpi还没有安装，则直接返回没有找到的状态值。

解析该 FV 的 FvPpi 已经存在，则可以调用 FvPpi 的 FindFileByName()服务查找符合条件的文件模块，并返回查找的状态值。

PeiFfsGetFileInfo 通过文件句柄获得文件单元的基本信息，包括类型、GUID 及数据。

通过文件句柄获得文件单元的基本信息。该函数的实现是基于 FvPpi 的 GetFileInfo()服务。

根据输入的文件句柄查找该文件所在的 PeiCore 内部维护的 FV 句柄结构。

逻辑与前面一致：如果对应的 PeiCore 内部维护的 FV 句柄结构没有找到，或者该 FV 数据结构的 FvPpi还没有安装，则直接返回不合法的状态值。

最后return 解析该 FV 的 FvPpi 已经存在，则可以调用 FvPpi 的 GetFileInfo ()服务获得该文件的基本信息，并返回获得文件信息的状态值。

PeiFfsGetVolumeInfo 通过 FV 句柄获得 FV 空间的基本信息，包括类型、格式、属性及数据。

通过 FV 句柄获得 FV 数据空间的基本信息。该函数的实现是基于 FvPpi 的 GetVolumeInfo ()服务。

逻辑与前两个函数一致，最后得return则是解析该 FV 的 FvPpi 已经存在，则可以调用 FvPpi 的 GetVolumeInfo()服务获得该 FV 的基本信息，并返回获得 FV 信息的状态值。

PeiRegisterForShadow 注册 PEI 模块请求在物理内存中运行的申请。


给当前正在运行的 PEIM（PEI 阶段驱动程序）注册影子加载标记，标记该 PEIM 需要在永久内存就绪之后执行 Shadow（影子拷贝)：把驱动代码从 Flash‑ROM 拷贝到高速永久内存里运行，加快执行速度。

note：PEI 前期一切驱动都是直接从 SPI‑Flash 闪存上原地执行（XIP，Execute‑In‑Place），Flash 读取速度慢；等到系统永久内存 DRAM 初始化完毕，PEI‑Core 会把所有已经调用 PeiRegisterForShadow() 的 PEIM 复制进 DRAM，之后在内存中运行，也就是 Shadow。

GetPeiServicesTablePointer() 获取当前 PEI 服务表指针；

宏 PEI_CORE_INSTANCE_FROM_PS_THIS 通过服务表反向寻址拿到全局 PEI‑Core 实例 PEI_CORE_INSTANCE； Private 里面维护固件卷 FV 信息、每个 PEIM 的运行状态、当前正在执行的驱动句柄。

CurrentFileHandle：PEI‑Core 当前正在调度执行的 PEIM 文件句柄；

该 API 只允许 PEIM 在自身入口内调用；

如果别的驱动句柄传入进来，直接返回 EFI_NOT_FOUND，禁止替其他 PEIM 注册影子。

只要当前驱动状态 ≥ PEIM_STATE_REGISTER_FOR_SHADOW，代表已经注册影子或者驱动已经跑完，再次调用接口直接返回 EFI_ALREADY_STARTED，防止重复标记。

将当前 PEIM 状态切换为申请影子拷贝标记。

后续 PEI‑Core 在 DRAM 永久内存初始化完成之后，遍历全部 PEIM，凡是标记为 PEIM_STATE_REGISTER_FOR_SHADOW 的驱动，都会从 Flash 拷贝至 DRAM 内存执行。

PeiFfsFindSectionData3

在指定 FFS‑File 文件内，按段类型、实例序号查找 Section 区块，同时输出校验认证状态，属于固件文件系统 FFS 的上层查找接口。

合法性校验：

  • 文件句柄无法映射到合法固件卷

  • 该固件卷没有安装 FvPPI（固件卷访问协议）

    返回 EFI_NOT_FOUND，找不到对应固件资源。

  1. 校验 PPI 结构体魔数 Signature，防止野指针、错误结构体；
  2. 严格匹配协议 Revision 版本；

Note 只有新版固件卷 PPI 才具备 FindSectionByType2 接口。

PEI‑Core 本身不会实现 FFS 文件解析逻辑，全部委托平台 / 固件卷驱动安装的 EFI_PEI_FIRMWARE_VOLUME_PPI。FindSectionByType2 能力：

PeiFfsGetFileInfo2

根据 FFS 文件句柄，获取固件文件的扩展文件信息结构体 EFI_FV_FILE_INFO2，新版结构体携带固件验签、安全认证状态。

Signature 校验：确认该指针确实是 EFI_PEI_FIRMWARE_VOLUME_PPI，防范野指针；

Revision 协议版本校验：只有最新修订版固件卷 PPI 才提供 GetFileInfo2；

PEI‑Core 只充当转发层，实际 FFS 文件信息读取交由固件卷 PPI 实现。

不同存储介质（SPI‑Flash、eMMC）各自实现 FvPPI，PEI 内核不需要关心底层存储。

PeiFreePages 释放由 PeiAllocatePages 申请的物理页内存。

PEI 阶段的内存管理依靠 HOB (Hand‑Off Block)，内存分配信息存放在 EFI_HOB_TYPE_MEMORY_ALLOCATION 内存分配 HOB，不存在传统堆空闲链表；释放内存本质就是修改、拆分内存分配 HOB，把内存标记回普通可用内存 EfiConventionalMemory。

EFI_PAGE_SHIFT = 12，一页大小 4KB；

页数左移 12 位换算成总字节；

End = 起始地址 + 总字节 − 1，得到区间最后一字节地址。

Pages 等于 0，非法；

起始物理地址没有按照 4KB 页对齐；EFI_PAGE_MASK = 0xFFF；

地址溢出造成 Start >= End；

任意条件命中，返回 EFI_INVALID_PARAMETER。

通过 PEI 服务表反向取出 PEI_CORE_INSTANCE； HOB 链表还未初始化，内存管理服务尚未就绪，返回 EFI_NOT_AVAILABLE_YET。 时间节点：DRAM 永久内存初始化完毕之后才会初始化 HOB 链表；早期 TempRam 临时内存阶段不能使用 FreePages。

1.MemoryType != EfiConventionalMemory

只查找已经被占用的内存 HOB；普通空闲内存不会执行释放；

释放起始地址大于等于 HOB 内存基址

释放区间的末尾地址不能超过该 HOB 内存区间

之后保存该内存分配 HOB 并跳出循环；循环继续遍历下一条内存分配 HOB。

1）UpdateOrSplitMemoryAllocationHob

核心 HOB 处理函数，存在三种场景：

  1. 释放区间刚好等于整块已分配内存 → 直接清除该占用标记；
  2. 释放的是分配块头部一段内存 → 拆分 HOB，剩余保留占用；
  3. 释放中间或者尾部区间 → 拆分生成新的 HOB 条目，被释放部分设置成 EfiConventionalMemory（可用常规内存）。

2）FreeMemoryAllocationHob

当该内存分配 HOB 内部已经不存在被占用的内存区域，就把这条空的内存分配 HOB 从 HOB 链表移除。

找不到对应内存分配 HOB → 返回 EFI_NOT_FOUND，代表该段地址并不是通过 AllocatePages 申请而来。

结合前面内存操作得函数，PEI 得内存操作逻辑大体如下：
PEI 阶段内存管理底层原理总结 PEI 永久内存不使用传统双向空闲链表，全部依靠 HOB 描述内存区块；

AllocatePages：切割 EfiConventionalMemory 空闲 HOB，新建内存占用 HOB； FreePages：遍历内存分配 HOB，拆分区块、把内存类型改回常规可用内存；

HOB 是顺序链表，每次释放都会遍历，因此频繁分配释放性能较差；

PEI 属于一次性初始化阶段，不会长时间频繁操作内存。
