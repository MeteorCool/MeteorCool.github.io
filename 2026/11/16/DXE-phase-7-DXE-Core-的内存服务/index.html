DXE phase 7 DXE Core 的内存服务

DXE 阶段的动态内存管理服务需要依靠GCD 服务，也就是全局一致性域。

对于GCD来说，他的功能类似于内存的账本，对内存做登记，记账的功能，但他本身不做内存分配动作。GCD 相当于是整个系统的物理内存大地图。

1.GCD 会记录每一段物理内存是什么类型：可用DRAM，SPI ROM ，MMIO 还保留的区域

2.GCD 会记录物理内存的cache 权限 （WB/UC/WC）

PEI 阶段会把内存信息通过HOB 传递给DXE，DXE core 则会将可用内存注册到GCD 当中，PCI 枚举如果发现新的MMIO也会注册进去。

GCD 对外也提供查询一段地址是什么资源、修改缓存属性、新增 / 删掉一段地址区间 的功能。

DXE 内存分配器（AllocatePages / AllocatePool） 则是管控内存分发的动作

  1. 先去 GCD 地图里找：标记为可用普通 DRAM的区域；
  2. 在这片合法 DRAM 上面，自己维护空闲页链表、堆链表；
  3. AllocatePages：按整页去 GCD 合法内存里拿连续物理页；
  4. AllocatePool：在已经拿到的页面里，再切小块，做堆内存分配；
  5. Free 的时候，把页面 / 小块放回空闲链表。

DXE Core 内存服务关键函数分析

1.RemoveMemoryMapEntry

该函数逻辑很简单，它做了两件事情：首先把记录某块存储空间信息的节点从链表中删除，然后 **if (Entry->FromPages)**对该节点的来源进行判断，如果它是从动态存储空间中分配获得的，那么就把这个节点插入到 mFreeMemoryMapEntryList 这个链表中以供后续的存储分配用来记录存储空间信息。使用mFreeMemoryMapEntryList 可以充分利用已经分配的动态存储空间，这样可以避免频繁的分配、释放用于保存存储空间信息节点的存储空间。

2.CoreAddRange

作用：把一段物理地址区间，加入 DXE 内存管理器的 gMemoryMap 链表（DXE 自己维护的内存区间表，≠GCD、≠UEFI Runtime MemoryMap） 调用时机：DXE 初始化可用内存、或者新增一段可用内存时调用；它是给内存分配器新增一段可管理内存区间

把物理地址 0 开始的第一页全部清零。

  • 这段内存是普通可用内存 EfiConventionalMemory
  • 起始地址是 0，包含 0 号页
  • PCD PcdNullPointerDetectionPropertyMask 的 BIT0 没有开启（开启 = 不做清零）

更新内存 Map 版本号 + 触发内存变更事件

MemoryMapKey：内存 Map 版本 Key。 每次内存布局改动（增删区间）就 + 1。上层调用 GetMemoryMap() 时会带回这个 Key；驱动可以用 Key 判断内存 Map 有没有发生变化。

触发 gEfiEventMemoryMapChangeGuid 事件组。 凡是注册了这个事件的驱动，会收到通知：内存布局变了。

相邻区间合并
只有内存 Type、Attribute 完全一样，才允许合并（类型不一样、缓存属性不一样，绝对不能合并）。 遍历 gMemoryMap 里所有已存在的内存段：

  1. 左边旧段的末尾 + 1 = 新区段起始 → 把新区段的 Start 改成旧段 Start，把旧节点摘除（RemoveMemoryMapEntry）
  2. 右边旧段的起始 = 新区段末尾 + 1 → 把新区段的 End 改成旧段 End，把旧节点摘除

新建节点，插入 gMemoryMap 链表

函数完整逻辑流程：CoreAddRange 向 DXE 内存管理器注册一段连续物理内存区间：

  1. 先处理 0 号页清零（普通可用内存才清）；

  2. 版本号 + 1，触发内存变更事件；

  3. 遍历已有内存段，把同类型、同属性、相邻的区间合并，旧节点摘除；

  4. 在栈上创建新 MEMORY_MAP 节点，把合并后的大区间插入 gMemoryMap 链表

  5. AllocateMemoryMapEntry

    该 函 数 的 功 能 是 获 取 一 个动态分配的 存 储 空 间 信 息 节 点 。 if (IsListEmpty (&mFreeMemoryMapEntryList)) 处 理
    mFreeMemoryMapEntryList 为空的情况，即如果所有曾经分配过的用于存储空间信息的节点都被用掉了，那么我们就需要去获得一块新的存储空间，CoreAllocatePoolPages 用来获取这样一个新的页面。如果成功获得了新空间，那么在for循环当中，这块空间被分割成一个个 MEMORY_MAP 单元并加入到 mFreeMemoryMapEntryList 中。这样，后续的需要动态存储空间信息的节点就可以在这个链表中获得一个存储描述单元。

  6. CoreFreeMemoryMapStack

该函数的功能为将临时数组 mMapStack 中的存储空间信息转移到动态分配的存储空间里，由于 mMapStack 的容量有限，这种转移操作是很有必要的。

使用了一个全局变量 mFreeMapStack 用于防止该函数被重入。Entry = AllocateMemoryMapEntry (); 行从 mFreeMemoryMapEntryList 中获得
一个存储信息节点单元 Entry。

对于临时数组中已有的存储空间信息，

完成了存储信息节点的转移，

开始的 for 循环遍历了整个存储信息链表来给要加入的存储信息节点找一个恰当的插入位置使得所有动态分配的节点存储信息的起始地址从头节点开始向后 Backward 按照从小到大的顺序排列。

则处理了另外一种情况即临时数组元素中并没有存储信息，那么已经获得的动态存储信息节点就直接被放到了保存空闲存储信息节点的链表 mFreeMemoryMapEntryList中。

重置了重入保护变量 mFreeMapStack 表示存储空间信息转移的工作已经结束。

5.PromoteMemoryResource

这个函数作为DXE Core 和GCD 之间沟通的桥梁。其作用是将GCD 内标记的保留的，已初始化的可用的内存升级为系统可用的普通内存，交给内存管理器分配管理。

CoreAcquireGcdMemoryLock ();

GCD 内存锁，保护 GCD 全局链表 mGcdMemorySpaceMap，防止并发修改 GCD 账本。

遍历GCD全部内存列表，CR 反向找到GCD 节点地址。

内存升级的条件：

  1. 当前 GCD 类型 = EfiGcdMemoryTypeReserved
  2. 这段内存结束地址 < MAX_ALLOC_ADDRESS：不超过分配器支持的最大地址（一般是 4G 或者平台限定地址，避开高地址 MMIO / 保留区域）
  3. Capabilities 同时具备：PRESENT（内存存在） + INITIALIZED（已经初始化），但是缺少 TESTED（还没打上 TESTED 标记）

  • 如果带 EFI_MEMORY_MORE_RELIABLE 标记 → 升级为高可靠内存类型 EfiGcdMemoryTypeMoreReliable

  • 否则 → 升级为普通系统内存 EfiGcdMemoryTypeSystemMemory

    这一步是告诉GCD 当前内存属于可用内存。

内存已经自检完成，可以分配，同时handle 归属于DXECore

调用前面提的coreaddrange，把这段内存区间，加入 DXE 内存分配器的 gMemoryMap 链表，类型标记为 EfiConventionalMemory，这是UEFI的普通内存

CoreFreeMemoryMapStack ： 把 CoreAddRange 产生的栈上临时 MEMORY_MAP 节点迁移成 Page 常驻节点，防止指针跑飞。

升级完成标志位 true

释放内存锁定。

上面 GCD 遍历没有找到任何可以升级的内存（Promoted 还是 FALSE），进入 Freed Memory Guard 功能。

  • PromoteGuardedFreePages：内存安全保护功能（Guard Page），为了检测内存越界，会预留一部分空闲页作为守卫页； 当系统内存紧张的时候，可以把一部分 Guard 守卫页释放出来，变成可用内存。
  • 如果成功释放了 Guard 页，同样调用 CoreAddRange 加入内存分配器。

6.CoreAddMemoryDescriptor

CoreAddMemoryDescriptor 是上层注册一段内存区间到 DXE 内存分配器的封装函数：先做页对齐、类型合法性校验；持有内存锁调用 CoreAddRange+CoreFreeMemoryMapStack 完成区间注册；之后自动应用内存保护页表策略；可选执行固定地址加载钩子；最后初始化内存类型统计容器。

其他内存管理的函数汇总：

函数名称 函数作用
CoreConvertPages 页面类型转换。将一段已经分配好的页面，修改它的 EFI_MEMORY_TYPE（比如 BootServicesData → ConventionalMemory），同步更新 gMemoryMap、内存保护策略，不做物理页的搬移。
CoreFindFreePagesI 内部查找空闲页（不带锁版本）。在空闲页链表中搜寻满足页数、地址上限、对齐要求的连续空闲物理页；仅内部调用，调用方必须提前持有 gMemoryLock。
CoreFindFreePages 查找空闲页（带锁封装）。先获取内存锁，调用 CoreFindFreePagesI 查找连续空闲页，查找完成释放锁；AllocatePages 的前置查找入口。
CoreAllocatePages AllocatePages 核心实现。根据分配类型（AnyPages/MaxAddress/Address）调用 CoreFindFreePages 找空闲页；找不到时调用 PromoteMemoryResource 尝试解锁更多内存；找到后标记页面为已分配、更新内存统计。
CoreFreePages 释放物理页。把不再使用的连续页面放回空闲页链表；执行相邻空闲块合并，更新内存类型统计；是 FreePages 的底层实现。
MergeMemoryMapDescriptor 合并内存描述符。遍历 gMemoryMap，把同 Type、同 Attribute、地址相邻的 MEMORY_MAP 节点合并为一个大区间，减少链表节点数量，降低遍历开销，CoreAddRange 内部依赖此逻辑。
CoreGetMemoryMap GetMemoryMap 底层实现。遍历 gMemoryMap，把 DXE 内部 MEMORY_MAP 链表，转换成 UEFI 标准 EFI_MEMORY_DESCRIPTOR，输出给上层（驱动 / RT 服务），同时返回 MemoryMapKey。
CoreTerminateMemoryMap 销毁 DXE 内存映射。DXE 退出 Boot Services 阶段时调用，清理 gMemoryMap、空闲页链表、空闲描述符池 mFreeMemoryMapEntryList，停止内存分配服务。
CoreAllocatePoolI Pool 分配内部无锁版本。从 Pool 堆里寻找匹配大小的空闲小块；不足时向页分配器申请新页面扩充 Pool；调用方必须持有 gMemoryLock。
CoreFreePoolI Pool 释放内部无锁版本。把 Pool 小块放回空闲堆链表，尝试和前后相邻空闲 Pool 块合并；调用方必须持有 gMemoryLock。

DXE core 的内存管理流程简述如下：

整体分为四层：GCD 地址资源层 → DXE 内存管理层（gMemoryMap） → Page 页分配子系统 → Pool 小块堆子系统

  1. PEI 将 DRAM 注册进 GCD，初始标记为 Reserved，暂不可分配；
  2. 业务发起 AllocatePages / AllocatePool，优先在空闲链表查找；
  3. 空闲不足时触发 PromoteMemoryResource，从 GCD 解锁 Reserved 内存，经由 CoreAddRange + CoreFreeMemoryMapStack 加入 DXE 内存管理链表；
  4. 释放内存时自动合并相邻空闲块，减少碎片；
  5. CoreGetMemoryMap 把内部链表转为标准 UEFI 内存描述符对外输出；
  6. ExitBootServices 阶段调用 CoreTerminateMemoryMap 销毁 DXE 内存管理结构，停止 BootService 内存分配。
