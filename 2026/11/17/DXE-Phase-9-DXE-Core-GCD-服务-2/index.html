GCD 服务关键函数分析

CoreInitializeGcdServices

CoreInitializeMemoryServices 是先从 HOB 里挑一块可用内存，给 DxeCore 本身当运行栈 / 堆；

CoreInitializeGcdServices 才是正式初始化 GCD 全局地址空间管理服务，把 PEI 上报的所有资源 HOB 灌入 GCD，同时同步初始化 UEFI Memory Map，是 GCD 服务真正的入口。

函数整体流程如下：

  1. 读取 CPU HOB，获取系统地址空间宽度
  2. 初始化 GCD 内存空间链表、IO 空间链表（初始全是 NonExistent）
  3. 遍历 Resource HOB，批量调用 CoreInternalAddMemorySpace / CoreAddIoSpace 向 GCD 注册所有地址资源
  4. 先把 DxeCore 自身使用的那块内存，在 GCD 中标记为已分配
  5. 再次遍历 HOB，处理 MemoryAllocation HOB、FV HOB，在 GCD 标记占用 + 填充 UEFI Memory Map
  6. 遍历 GCD 整张 MemorySpaceMap，把剩余空闲系统内存注册成 EfiConventionalMemory；HOB 区域延后处理、HOB 重定位

CPU HOB 由 PEI 阶段（SEC/PEI Core）填充，记录：

  • 内存地址空间多少位（比如 48 位 → 物理地址上限 2^48 -1）
  • IO 地址空间多少位（x86 一般 16bit，0~0xFFFF）

这个值决定 GCD 初始根节点的 EndAddress。

初始化 GCD 全局链表（mGcdMemorySpaceMap /mGcdIoSpaceMap）

  • GCD 底层是有序链表管理地址区间，初始状态：整个地址空间标记为 NonExistent（不存在）
  • 内存空间一条根节点、IO 空间一条根节点
  • CoreDumpGcdMemorySpaceMap 是 DEBUG 打印，方便看 GCD 初始状态

核心：GCD 本质是区间分割管理器，后续 AddMemorySpace 就是把大的 NonExistent 区间切分成不同类型的子区间（SystemMemory、MMIO、Reserved、Persistent 等）

第一轮 HOB 遍历：Resource HOB 灌入 GCD（最重要的 for 循环）

只处理 EFI_HOB_TYPE_RESOURCE_DESCRIPTOR，根据 ResourceType + ResourceAttribute 翻译成 GCD 内部类型。翻译完成后进行校验掩码和修改GCD 链表，切割地址空间，注册对应的类型。

这一步完成后：GCD 已经知道整个物理地址空间每一段是什么类型（内存 / MMIO / 保留 / 持久内存），但是此时 GCD 只是 “知道资源存在”，还没有标记哪些已经被占用分配。 GCD 两个状态维度：资源类型（是什么） + 分配状态（是否被占用）。

标记 DxeCore 自身所用内存为已分配，CoreAllocateMemorySpace：在 GCD 中标记该段地址已分配，归属 Handle (gDxeCoreImageHandle)

注意：GCD 的 AllocateMemorySpace ≠ UEFI BS 的 AllocatePool/AllocatePages GCD 是底层地址空间占用登记；BS 内存服务是在 GCD 之上，管理 EFI Memory Map。

第二轮 HOB 遍历：处理 MemoryAllocation HOB、FV HOB

类 HOB：

  1. EFI_HOB_TYPE_MEMORY_ALLOCATION（PEI 预分配内存）

    • PEI 阶段已经占用的内存（比如 PEI 堆、PEI 栈、PPI 相关缓冲区）
    • 先 CoreAllocateMemorySpace：GCD 标记占用
    • 如果是 SystemMemory/MoreReliable，调用 CoreAddMemoryDescriptor：写入 UEFI Memory Map（EfiLoaderCode、EfiLoaderData、EfiACPIReclaimMemory 等）
    • 如果是 MemoryTypeInformation HOB，调用 UpdateMemoryStatistics，统计各类型内存占用 bin，给后续内存分配策略使用

  2. EFI_HOB_TYPE_FV（Firmware Volume）

    • FV 是 MMIO 空间，调用 CoreAllocateMemorySpace，标记这段 MMIO 被 FV 占用，GCD 登记。

    FV 本身不会进 EFI Memory Map，它属于 MMIO 资源。

    遍历 GCD MemorySpaceMap，把剩余空闲内存注册为 EfiConventionalMemory

CoreGetMemorySpaceMap：把 GCD 内部链表导出成数组快照，遍历所有 GCD 条目：

  • 只看 EfiGcdMemoryTypeSystemMemory / MoreReliable，并且ImageHandle == NULL（GCD 里还没被分配占用）

  • 页对齐起始地址、长度

  • 特殊分支：碰到 HOB 本身所在的那一段内存，先跳过，存入 MemorySpaceMapHobList

    原因：HOB 现在还在原始 PEI 内存里，如果直接加到 ConventionalMemory，后续分配内存可能把 HOB 覆盖掉，导致 HOB 链表损坏。

  • 其余空闲内存：

    CoreAddMemoryDescriptor(EfiConventionalMemory) + CoreAllocateMemorySpace

    到这里，常规可用内存已经加入 UEFI Memory Map，BS 的 AllocatePages 可以正常使用这片内存。

    HOB 重定位 + 延后处理 HOB 所在内存区间

    • 在已经建好的 Conventional Memory 里分配一块 Pool，把原始 HOB 链表拷贝过去
    • 更新全局 HOB 指针，后续所有驱动拿 HOB，都访问新拷贝后的 HOB
    • 拷贝完成、HOB 安全了，再把刚才跳过的原始 HOB 所在内存，加入 ConventionalMemory，交给内存管理

其他GCD函数功能与作用简述

函数名 核心功能简述
CoreDumpGcdMemorySpaceMap 调试函数，遍历并打印 GCD 内存空间（GCD Map）所有条目，输出基地址、长度、类型、属性、权限等信息，调试 GCD 资源分裂 / 合并、属性异常时使用
CoreAllocateGcdMapEntry 从 DXE 池分配一个 GCD_MAP 结构体节点，初始化基础字段；GCD 用双向链表管理地址区间，新增区间时先分配 entry
CoreInsertGcdMapEntry 将分配好的 GCD_MAP 节点插入 GCD 空间链表（MemorySpaceMap / IoSpaceMap），按基地址排序，同时执行相邻区间合并（coalesce）
CoreSearchGcdMapEntry 根据输入地址，二分 / 顺序查找 GCD 链表，找到包含该地址的 GCD_MAP 条目；是查询、修改、分裂区间的基础查询函数
CoreConvertSpace 地址空间类型转换，在 GCD 内部完成 EFI 内存类型、资源属性到 GCD 内部空间类型（GcdMemoryType）、权限掩码的转换；也用于资源 HOB 属性转换
CoreAllocateSpaceCheckEntry GCD 分配前校验函数：检查目标地址区间是否空闲、是否和已有区间重叠、对齐是否合法、属性是否兼容；分配失败的前置判断
CoreAllocateSpace GCD 底层通用分配入口，支持 Memory Space / IO Space；调用查找、校验、分裂现有区间、分配新 entry、插入链表，是分配的公共底座
CoreAllocateMemorySpace 面向内存空间的封装，调用 CoreAllocateSpace，专门用于分配内存地址资源（区别于 IO 空间）
CoreAddMemorySpace 向 GCD 内存空间新增一段资源区间（PEI HOB 资源注册阶段主力调用），标记资源存在，初始属性由 HOB 传入
CoreFreeMemorySpace 释放一段内存地址区间，将对应区间标记为空闲，尝试和前后空闲区间合并
CoreRemoveMemorySpace 从 GCD 内存空间链表移除指定区间（销毁资源，和 Free 不同：Free 是标记空闲，Remove 是直接拿掉这段资源，一般用于资源被回收、热拔设备移除资源）
CoreGetMemorySpaceDescriptor 查询指定地址对应的 GCD 内存描述符，返回基址、长度、类型、属性、权限；对外服务 GetMemorySpaceDescriptor 的底层实现
CoreSetMemorySpaceAttributes 修改一段内存区间的 GCD 属性（缓存属性、读写权限等）；内部会先查找 entry，必要时分裂区间，更新属性，同步给 MTRR 相关逻辑
CoreGetIoSpaceMap 查询 IO 地址空间的 GCD 映射条目，获取 IO 空间的基址、长度、属性，是 IO 空间查询接口底层

上述函数逻辑关系如下：

CD 整体两条主线：资源注册初始化流、资源分配 / 查询 / 修改流

  1. 初始化阶段（CoreInitializeGcdServices） 遍历 PEI Resource HOB → CoreConvertSpace 做属性类型转换 → CoreAddMemorySpace``CoreAddMemorySpace 内部：CoreAllocateGcdMapEntry 分配节点 → CoreInsertGcdMapEntry 插入并合并到 MemorySpaceMap 链表。
  2. 资源分配流程（Allocate）CoreAllocateMemorySpace → CoreAllocateSpace（通用底座） → CoreSearchGcdMapEntry 查找区间 → CoreAllocateSpaceCheckEntry 合法性校验（重叠、对齐） → 必要时分裂原有 GCD 条目 → CoreAllocateGcdMapEntry 新建条目 → CoreInsertGcdMapEntry 插入链表。
  3. 查询 & 属性修改流程CoreGetMemorySpaceDescriptor / CoreSetMemorySpaceAttributes / CoreGetIoSpaceMap 全部先调用 CoreSearchGcdMapEntry 定位地址所属条目；SetAttributes 会按需分裂区间后更新属性。
  4. 释放 / 移除流程CoreFreeMemorySpace：查找条目 → 标记为空闲 → CoreInsertGcdMapEntry 触发相邻空闲合并；CoreRemoveMemorySpace：查找条目 → 直接从链表摘除，不保留资源。
  5. 调试分支CoreDumpGcdMemorySpaceMap：独立调试入口，遍历 GCD 链表打印，开发调试时手动调用，不参与正常资源管理路径。
