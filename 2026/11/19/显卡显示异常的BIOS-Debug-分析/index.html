G710 基于Intel ADL 平台显示白屏问题分析

问题描述：ADL 主板PCIE X16 接上G710 进BIOS 节目显示白屏，其他显卡正常，集显（主板原生接口）正常，进OS 后正常。不同CPU 情况一致。

问题定位：使用其他显卡功能正常，该显卡在其他主板工作正常，显卡无问题，说明问题是两者搭配产生的兼容性问题。进入setup 键盘灯正常操作，非宕机问题，问题定位在显示功能模块上。

梳理显卡工作流程，依次检查问题出在什么地方：

GOP 从DXE 阶段开始工作：
① PCI Bus DXE 设备枚举与资源分配检查：是否有发现显卡，是否有针对分别Bar，是否按照PCIIO 驱动成功

结果 Install EFI_PCI_IO_PROTOCOL
说明PCI 模块工作正常

② GOP 驱动执行流 & EFI_GRAPHICS_OUTPUT_PROTOCOL 状态检查

GOP 标准执行时序：DriverBindingStart() → PciIo 配置显卡 → PciIo->EnableBusMaster() → SetMode() → 安装EFI_GRAPHICS_OUTPUT_PROTOCOL；

结果：

GOP 驱动执行正常，setmode 未返回error，FB 成功分配，继续下一步检查

③后续GPU 会通过DMA 读取相关信息（像素画图），一般情况下，GPU 可直接访问DMA 实现该功能，但Intel 为了安全保护，提供了全新的VT-D 技术，会将对应的地址信息重新映射，ADL 平台当前VDT enable，所以我们需要考虑重映射是否成功，是否能正常读取到DMA 信息

GPU 发起 DMA Read 读取 FrameBuffer：

根据协议，当vd-t 开启，iommu 协议存在，那么GPU 就不可以直接访问DMA，当存在设备访问时，需要调用IoMmuSetAttribute来更新属性来请求访问

在实际debug 过程当中，发现该显卡未调用这个通道，说明该显卡未通过IOMMU 请求DMA，怀疑是通过GPU 直接访问DMA 但是被拒，无法获取FB 信息

Disable ControlIommu 进行二次验证测试，显示功能正常。

判定显卡在读取IOMMU 出现异常。

查阅资料，由于710 显卡属于早期产品，内部固件不支持IOMMU 方案去读取FB，

增加简易补丁，当侦测到710 显卡接入时，修改IOMMU default 为disable 。
