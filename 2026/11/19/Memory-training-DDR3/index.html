Memory training (DDR3)

  1. Memory training 是什么？

    一般来说，memory training 是系统开机上电之后，对内存进行的一次时序校准动作，因为内存中有大量的时序参数，每个参数都需要精准的时序控制，为了避免内存与系统之间的不同步，上电后需要进行一次training之后才允许开机。

  2. Memory training 流程

    参考JEDEC JESD79-3 SPEC ，提供了简化状态机图：

    ① power on 上电

    ②reset procedure 程序复位过程

    ③initialization 初始化

    ​ 对于SO-DIMM，系统会通过SMBUS来读取DIMM上SPD内关于内存模组的配置信息如P-BANK数量、电压、行地址/列地址数量、位宽、各种主要操作时序（如CL，tRCD,，tRP，tRAS等），并以此设定内存的工作参数。

    ​ 而对于ON-Board memory，省掉了SPD，这些内存的配置信息放在了BIOS内，开机时透过我们主板设定的PCB_ID来选择对应的配置信息。

    参考JEDEC JESD79-3 SPEC，DDR 初始化时序如下

    Power up前RESET#电平要低于0.2VDD，Power up后RESET#要保持为low至少200us，在RESET#被拉高之前，CKE至少要拉低10ns，Power up（0.3V~VDDmin）时间要在200ms以内。

    RESET# 拉高后，等待500us，CKE assert，在此时间内，DRAM进行内部的状态初始化，初始化进程与外部clk无关。Clocks(CK，CK#)在CKE active之前要建立和保持至少10ns，最大5 tCK。

    CKE 拉高之后，至少等待tXPR时间，将第一个MRS命令载入Mode Register 2，之后隔tMRD时间，顺序将MRS命令载入MR3,MR1,MR0和进行DLL reset。

    发送ZQCL命令，进行ZQ校准。

    DDR3进入正常操作模式。

④ZQ calibration ZQ校准 ZQCL+ZQCS

​ ZQCL: 上电初始化后，用完成校准ZQ电阻。ZQCL会触发DRAM内部的校准引擎， 一旦校准完成，校准后的值会传递到DRAM的IO管脚上，并反映为输出驱动和ODT阻值。

	ZQCS: 周期性的校准，能够跟随电压和温度的变化而变化。校准需要更短的时间窗口， 一次校准，可以有效的纠正最小0.5%的RON和RTT电阻。

⑤进入idle状态（根据具体情况选择进入5.1~5.4）

Idle状态：所有的bank必须预先充电，所有时序满足，DRAM的ODT电阻。RTT必须为高阻。

​ 5.1 配置MRS，MPR寄存器，write leveling

​ 模式寄存器(MR, Mode Register)的设置，简称MRS（MR Set），这一工作由CPU在BIOS的控制下进行，寄存器的信息由地址线来提供。模式寄存器MR没有缺省值，因此必须在上电或者复位后被完全初始化，才能使DDR正常工作。正常工作模式下，MR也可以被重新写入。

MPR : Multi-Purpose Register 多用途寄存器。存储在MPR中的信息可为:

  1. predefined system timing calibration bit sequence(固定码流供timing校正)；

  2. on die thermal sensor information (optional);

​ • 为了更好的对DDR3 SDRAM做timing calibration，MPR read command可将predefined bit sequence(0-1-0-1-0-1-0-1)读出至数据总线上，在此data read期间，memory controller会对系统timing做校正直到timing达到最优化。

​ • 当MR3 A[2] = 1时，MPR被enable，此后所有的读取命令都指向MPR，预先定义的0-1数据码流被读出，直到系统timing最优化；当MR3 A[2] = 0时，MPR 被disable，读写操作恢复正常.

5.2 self-refresh 自刷新。

5.3 refreshing 刷新 （DDR3还新增了局部自刷新(RASR)和根据温度自刷新(SAT)功能）。

​ RASR: 局部自刷新（RASR，Partial Array Self-Refresh）是DDR3的一个可选项，通过这一功能，DDR3内存芯片可以只刷新部分逻辑Bank，而不是全部刷新，从而最大限度的减少因自刷新产生的电力消耗。

​ SAT: 根据温度自动自刷新（SRT Self-Refresh Temperature）为了最大的节省电力，DDR3采用了一种新型的自动自刷新设计 （ASR，Automatic Self-Refresh）。当开始ASR之后，将通过一个内置于DRAM芯片的温度传感器来控制刷新的频率，因为刷新频率高的话，消电就大，温度也随之 升高。而温度传感器则在保证数据不丢失的情况下，尽量减少刷新频率，降低工作温度。

5.4 precharge power down 预充电。

​ 由于SDRAM 的寻址具体独占性，所以在进行完读写操作后，如果要对同一L-Bank 的另一行进行寻址，就要将原来有效（工作）的行关闭，重新发送行/列地址。L-Bank 关闭现有工作行，准备打开新行的操作就是预充电（Precharge）。预充电是一种对工作行中所有存储体进行数据重写，并对行地址进行复位，同时释放S-AMP（重新加入比较电压），以准备新的工作。

⑥.发送activating命令。

⑦Bank active

​ 发送Bank和Raw地址。（BA0-BA2选择BANK、A0-A15选择Row）

⑧Writing 写操作

​ 发送Write命令并发含带突发操作的起始Column地址（A0-A10），并确定是否发布自动预充电命令（通过A10）和选择BC4或BL8模式（通过A12）。

⑨Reading 读操作

​ 发送Read命令并发含带突发操作的起始Column地址（A0-A10），并确定是否发布自动预充电命令（通过A10）和选择BC4或BL8模式（通过A12）。

DDR3的training过程中遇到的一些时序的含义

l tRRD: 两个不同bank的行有效命令之间的最小时间间隔。

l tRC: 两个相同bank的行有效命令之间的最小时间间隔。

l tRCD: RAS to CAS delay (RAS至CAS延迟)，在发送列读写命令时必须要与行有效命令有一个间隔，这个间隔被定义为tRCD，也可以理解为行选通周期。这应该是根据芯片存储阵列电子元件响应时间(从一种状态到另一种状态变化的过程)所制定的延迟。 tRCD是芯片的一个重要时序参数。tRCD以时钟周期为单位，比如tRCD = 2，就代表延迟周期为两个时钟周期，具体到确切的时间，则要根据时钟频率而定。

l CL: 在CAS发出之后，仍要经过一定的时间才能有数据输出，从CAS与读取命令发出到第一笔数据输出的这段时间，被定义为CL（CAS Latency，CAS潜伏期）。由于CL只在读取时出现，所以CL又被称为读取潜伏期（RL，Read Latency）。CL的单位与tRCD一样，为时钟周期数，具体耗时由时钟频率决定。（存储体中晶体管的反应时间会造成数据不可能与CAS在同一上升沿触发，肯定要延后至少一个时钟周期。）

l **AL:**additive latency附加潜伏期。DDR2开始，为了解决DDR内存指令冲突，允许CAS信号紧跟RAS发送。但读/写操作并没有因此而提前，仍有要保证有足够的延迟/潜伏期，因此引入附加潜伏期的概念，与CL 一样，单位为时钟周期数。AL+CL 被定义为读取潜伏期（RL，Read Latency），相应的，DDR2还对写入潜伏期（WL，Write Latency）制定了标准，WL是指从写入命令发出到第一笔数据输入的潜伏期。

l tAC: 由于芯片体积的原因，存储单元中的电容容量很小，所以信号要经过放大来保证其有效的识别性，这个放大/驱动工作由S-AMP负责，一个存储体对应一个S-AMP通道。但它要有一个准备时间才能保证信号的发送强度（事前还要进行电压比较以进行逻辑电平的判断），因此从数据I/O总线上有数据输出之前的一个时钟上升沿开始，数据即已传向S-AMP，也就是说此时数据已经被触发，经过一定的驱动时间最终传向数据I/O总线进行输出，这段时间我们称之为tAC（Access Time from CLK，时钟触发后的访问时间）。tAC的单位是ns，对于不同的频率各有不同的明确规定，但必须要小于一个时钟周期，否则会因访问时过长而使效率降低。

l tWR: 写入/校正时间（tWR，Write Recovery Time），写操作虽然是0延迟进行，但资料并不是即时地写入存储电容，因为选通三极管(就如读取时一样)与电容的充电必须要有一段时间，所以资料的真正写入需要一定的周期来保证。这个操作也被称作写回（Write Back）。tWR 至少占用一个时钟周期或再多一点（时钟频率越高，tWR 占用周期越多）。

l tRP: Precharge command Period 预充电有效周期，SDRAM的寻址具有独占性，在同一时间只能打开同一Bank的一行，如果要对同一Bank的另一行进行定址，就要将原來有效(工作)的行关闭，重新发送/行列地址。关闭现有工作行，准备打开新行的操作就是预充电(precharge)。在发出预充电命令之后，要经过一段时间才能允许发送RAS行有效命令打开新的工作行，这个间隔被称为给出tRP。

l tRAS：（Active to Precharge Command，行有效至预充电命令间隔周期）。它有一个范围，对于PC133 标准，一般是预充电命令至少要在行有效命令5 个时钟周期之后发出，最长间隔视芯片而异（基本在120000ns 左右），否则工作行的数据将有丢失的危险。
